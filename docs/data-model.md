This document describes the data models used in GPT Memory Store, including domain models, persistence models, and the mapping between them.

## Domain Model: GptMemory

**Location:** `GptMemoryStore/Service/Models/GptMemory.cs`

```csharp
public sealed class GptMemory
{
    public string Id { get; set; } = Guid.NewGuid().ToString();
    public DateTimeOffset CreatedDateTime { get; set; } = DateTimeOffset.Now;
    public DateTimeOffset? UpdatedDateTime { get; set; }
    public string Content { get; set; }
    public string Source { get; set; }
    public decimal Confidence { get; set; }
}
```

### Field Details

| Property | Type | Default | Description |
|----------|------|---------|-------------|
| `Id` | string | `Guid.NewGuid().ToString()` | Unique identifier (GUID v4) |
| `CreatedDateTime` | DateTimeOffset | `DateTimeOffset.Now` | Creation timestamp (local time with offset) |
| `UpdatedDateTime` | DateTimeOffset? | `null` | Last revision timestamp; null if never revised |
| `Content` | string | Required (no default) | Free-text memory content |
| `Source` | string | Required (no default) | Free-text source identifier |
| `Confidence` | decimal | Required (no default) | Confidence value, typically 0.0–1.0 |

### Invariants

1. `Id` is generated by the domain model default, never accepted from client
2. `CreatedDateTime` is set once at creation and **never changes**
3. `UpdatedDateTime` is `null` initially, set on each revision
4. `Content`, `Source`, `Confidence` are mutable via update
5. No validation on `Confidence` range (0.0–1.0 is convention only)

### JSON Representation (Response)

```json
{
  "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "createdDateTime": "2024-01-15T10:30:00.0000000+00:00",
  "updatedDateTime": "2024-01-15T11:00:00.0000000+00:00",
  "content": "User prefers concise responses",
  "source": "profile-sync",
  "confidence": 0.95
}
```

## Mapping: GptMemoryMappingExtensions

**Location:** `GptMemoryStore/Service/Mapping/GptMemoryMappingExtensions.cs`

### Domain → Persistence

```csharp
internal static GptMemoryDataObject ToDataObject(this GptMemory domainModel) => new()
{
    Id = domainModel.Id,
    CreatedTimestamp = domainModel.CreatedDateTime.ToString(DateTimeFormat),
    UpdatedTimestamp = domainModel.UpdatedDateTime?.ToString(DateTimeFormat),
    Content = domainModel.Content,
    Source = domainModel.Source,
    Confidence = domainModel.Confidence
};
```

### Persistence → Domain

```csharp
internal static GptMemory ToDomainModel(this GptMemoryDataObject dataObject) => new()
{
    Id = dataObject.Id,
    CreatedDateTime = DateTimeOffset.Parse(dataObject.CreatedTimestamp),
    UpdatedDateTime = ParseNullableTimestamp(dataObject.UpdatedTimestamp),
    Content = dataObject.Content,
    Source = dataObject.Source,
    Confidence = dataObject.Confidence
};

private static DateTimeOffset? ParseNullableTimestamp(string timestamp)
{
    if (timestamp is null) return null;
    return DateTimeOffset.Parse(timestamp);
}
```

### Timestamp Format Constant

```csharp
private static string DateTimeFormat => "yyyy'-'MM'-'dd'T'HH':'mm':'ss'.'fffffffK";
```

**Format breakdown:**
- `yyyy` - 4-digit year
- `MM` - 2-digit month
- `dd` - 2-digit day
- `T` - literal 'T' separator
- `HH` - 2-digit hour (24-hour)
- `mm` - 2-digit minute
- `ss` - 2-digit second
- `fffffff` - 7-digit fractional seconds (100ns resolution)
- `K` - time zone offset (e.g., `+00:00`, `-05:00`)

**Example:** `2024-01-15T10:30:00.0000000+00:00`

### Round-Trip Guarantees

| Domain Property | Persistence Property | Round-Trip Preserved |
|-----------------|---------------------|---------------------|
| `Id` | `Id` | ✅ Exact |
| `CreatedDateTime` | `CreatedTimestamp` | ✅ Exact (7 decimal places) |
| `UpdatedDateTime` | `UpdatedTimestamp` | ✅ Exact (null ↔ null) |
| `Content` | `Content` | ✅ Exact |
| `Source` | `Source` | ✅ Exact |
| `Confidence` | `Confidence` | ✅ Exact (decimal) |

## Collection Ordering Rules

The collection endpoint (`GET /Memories`) returns memories ordered by:

1. **Primary:** `UpdatedDateTime` descending (most recently revised first)
2. **Secondary:** `CreatedDateTime` descending (for records never updated)

**Null handling:** `null` `UpdatedDateTime` values sort after all non-null values (standard LINQ behavior).

### Example Ordering

| Memory | CreatedDateTime | UpdatedDateTime | Order |
|--------|-----------------|-----------------|-------|
| A | 2024-01-10 | 2024-01-15 | 1 (most recent update) |
| B | 2024-01-12 | 2024-01-14 | 2 |
| C | 2024-01-15 | null | 3 (never updated, newest creation) |
| D | 2024-01-08 | null | 4 (never updated, oldest creation) |

## Store Initialization

**Location:** `GptMemoryStore/Startup.cs` → `CreateStoreIfMissing()`

```csharp
private static void CreateStoreIfMissing(string storePath)
{
    ArgumentException.ThrowIfNullOrWhiteSpace(storePath);
    string storeDirectory = Path.GetDirectoryName(storePath);
    if (!Directory.Exists(storeDirectory))
    {
        Directory.CreateDirectory(storeDirectory);
    }
    if (!File.Exists(storePath))
    {
        File.WriteAllText(storePath, "[]");
    }
}
```

### Behavior

1. Creates parent directory if missing
2. Creates file with empty JSON array `[]` if missing
3. Runs at **every startup** before middleware pipeline
4. No migration or schema versioning

### File Format

The store is a **JSON array** of `GptMemoryDataObject` objects. No wrapper object, no metadata.

```json
[]
```

```json
[
  { "Id": "...", "CreatedTimestamp": "...", "UpdatedTimestamp": "...", "Content": "...", "Source": "...", "Confidence": 0.95 },
  { "Id": "...", "CreatedTimestamp": "...", "UpdatedTimestamp": null, "Content": "...", "Source": "...", "Confidence": 0.5 }
]
```

## Concurrency Model

### Current Implementation

- `JsonRepository` (NuciDAL) loads entire file into memory on first access
- Mutations (`Add`, `Update`, `Remove`) modify in-memory collection
- `SaveChanges()` serializes entire collection to file
- **No file locking**, no transactions, no optimistic concurrency

### Implications

| Scenario | Behavior |
|----------|----------|
| Single instance, sequential requests | Safe |
| Single instance, concurrent requests | Potential race condition on `SaveChanges` |
| Multiple instances, shared filesystem | **Unsafe** - data loss likely |
| Multiple instances, separate files | Safe (but inconsistent data) |

### Recommendations

1. **Single instance only** for production deployments
2. If horizontal scaling needed, implement alternative `IFileRepository` (SQLite, PostgreSQL, etc.)
3. For read-heavy workloads, consider caching layer in front

## Migration and Versioning

### Current State

- **No migration framework** implemented
- **No schema version** in store file
- Breaking changes to `GptMemoryDataObject` require manual migration

### Adding Fields (Non-Breaking)

New optional fields with defaults work automatically:
```csharp
// Domain
public string NewField { get; set; } = "default";

// DataObject
public string NewField { get; set; } = "default";
```

### Removing/Changing Fields (Breaking)

Requires manual migration script:
```bash
# Example: rename Content → Text
jq 'map(.Text = .Content | del(.Content))' memories.json > memories-v2.json
mv memories-v2.json memories.json
```

### Timestamp Format Changes

The explicit format `yyyy'-'MM'-'dd'T'HH':'mm':'ss'.'fffffffK` is **stable**. Changing it would break parsing of existing records.

## Validation Rules

### Current Validation

| Layer | Validation |
|-------|------------|
| Controller | Model binding (required fields, types) |
| Service | None (trusts controller) |
| Repository | None (NuciDAL serializes what it's given) |
| Database | N/A (JSON file) |

### Missing Validation

- `Confidence` range (0.0–1.0) not enforced
- `Content`/`Source` length not limited
- `Id` format not validated (assumed GUID)
- No duplicate ID detection (repository may overwrite)

## Size Estimates

| Record Count | Approximate File Size |
|--------------|----------------------|
| 100 | ~50 KB |
| 1,000 | ~500 KB |
| 10,000 | ~5 MB |
| 100,000 | ~50 MB |

**Memory usage:** Entire file loaded into memory by NuciDAL. 100K records ≈ 50-100 MB RAM.

**Performance:** Linear scan for `Get(id)` and `GetAll()`. No indexing. Consider alternative repository for >10K records.
